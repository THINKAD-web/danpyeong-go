## 구현 전 검토 메모 (코드베이스 대조 결과)

| # | 항목 | 내용 | 상태 |
|---|---|---|---|
| R1 | 3-4 레이트리밋 | `(시험 코드 + IP)` 조합으로만 세면 **코드를 바꿀 때마다 한도가 새로 생겨** 6자리 코드 브루트포스 방어가 사라진다. 대안: **실패한 코드 조회만 IP당 분당 5회**로 세고(오타는 드묾), **성공한 응시 시작은 (코드+IP)당 분당 30회**로 넉넉하게 둔다. 교실 30명 문제는 풀리고 방어는 유지된다 | 결정 필요 |

| R3 | 연간 "2개월 절약" | 월 4,900 × 12 = 58,800원, 연 39,000원 → 19,800원(약 **4개월분**) 절약. 표기를 "4개월 절약" 또는 "34% 할인"으로 | 문구 수정 |

## Phase 2-A · 프리미엄 요금 체계 UI + 기능 게이팅 (11월)

### 2-A-1. 요금제 정의

| 구분 | Free | Pro | 학교 라이선스 |
|---|---|---|---|
| 대상 | 교사 개인 | 교사 개인 | 학년·학교 단위 |
| AI 문항 생성 | 월 8회 | 무제한 | 무제한 |
| 평가 저장 | 최근 5개 | 무제한 | 무제한 |
| 기본 채점·리포트 | ✅ | ✅ | ✅ |
| 오답 기반 보충 문항 | ❌ | ✅ (Phase 5-B) | ✅ |
| 누적 성장 리포트 | ❌ | ✅ | ✅ |
| 동학년 평가 공유 | 받기만 | 보내기+받기 | 전체 |
| PDF/Excel 내보내기 | 기본 | 커스텀 (학교 로고 등) | 커스텀 |
| 가격 | 0원 | 월 4,900원 / 연 39,000원 | 별도 협의 (연간) |

설계 원칙:
- 무료 월 8회 = 한 달에 단원 2~3개를 충분히 만들 수 있는 양. 너무 적으면 경험 자체를 못 하고 이탈, 너무 많으면 전환 동기가 없음.
- 평가 저장 5개 제한 = 무료 교사가 1학기분을 보관하려면 프로가 필요. 자연스러운 업그레이드 트리거. (→ R2)
- 학교 라이선스는 2027년 2학기 이후 본격 판매. Phase 2에서는 "문의하기" 버튼만 제공.

### 2-A-2. 기능 게이팅 구현

DB 스키마 변경 (→ R8: `User`에 반영):
```
plan: enum('free', 'pro', 'school') DEFAULT 'free'
plan_started_at: timestamp NULL
plan_expires_at: timestamp NULL
monthly_generation_count: int DEFAULT 0
generation_reset_at: timestamp  -- 매월 1일 리셋
```

- 문항 생성 API에 `checkGenerationQuota()` 추가. Free 플랜에서 월 8회를 넘기면 차단: "이번 달 무료 생성 횟수를 모두 사용했어요. 프로로 업그레이드하면 무제한으로 사용할 수 있어요." + 업그레이드 CTA.
- 평가 저장: Free 플랜에서 6번째 평가를 저장하면 가장 오래된 평가를 자동 삭제하지 **않는다**. 저장을 차단하고 "프로로 업그레이드하면 무제한 저장" 안내. 교사 데이터를 함부로 지우면 신뢰가 깨진다.
- Pro 기능(누적 성장 리포트, 커스텀 내보내기 등)은 UI에 보이되 클릭 시 "프로 기능입니다" 모달.
- 리셋: 게으른(lazy) 리셋 권장. `if (현재 월 !== reset_at 월) → count = 0, reset_at = now` (→ R8: 로그 집계로 대체 가능).

### 2-A-3. 요금제 페이지 `/pricing`
- 3컬럼 카드 (Free / Pro / 학교). Pro에 "추천" 뱃지.
- 로그인 상태면 Free 카드에 "현재 플랜" 표시.
- Pro 카드: 월간/연간 토글. 연간 선택 시 할인 표시 (→ R3).
- 학교 카드: "도입 문의하기" → 이메일 또는 폼.
- FAQ: "베타 기간에 만든 평가는 어떻게 되나요?" → "모든 기존 데이터는 유지됩니다."
- 비로그인 접근 가능. 랜딩 GNB에 "요금제" 링크.

### 2-A-4. 교사 대시보드 변경
- 상단: "Free 플랜 · 이번 달 3/8회 사용"
- 생성 버튼 옆 잔여 횟수 뱃지
- Pro 전용 기능에 🔒 + "Pro" 라벨
- 설정 페이지에 "구독 관리" 섹션 (결제 연결은 2-B)

## Phase 2-B · 결제 인프라 연동 (12월)

### 2-B-1. PG: 포트원 (PortOne) (→ R6: V2)
- 국내 PG 20여 곳 통합. 카드·카카오페이·네이버페이·토스페이.
- 프론트엔드 SDK + REST API.
- 월 거래 1억 미만이면 포트원 이용료 무료 (PG 수수료만 부담).
- 학교 라이선스 세금계산서에도 같은 인프라 활용 가능.

### 2-B-2. 연동 구조
```
[교사 브라우저] → 결제 요청
[포트원 JS SDK] → [PG사 결제창]
    ↓ 결제 완료 콜백
[/api/payments/complete]
    ↓ 포트원 REST API로 결제 검증 (금액은 서버 기준으로 대조)
    ↓ 성공 → DB 업데이트 (plan, plan_started_at, plan_expires_at)
    ↓ 실패 → 에러 응답
```

### 2-B-3. 구독 관리
- **월간**: 빌링키 정기결제. 매월 결제일 자동 갱신, 갱신 3일 전 이메일(→ R7). 해지하면 현재 기간이 끝날 때 Free로 전환.
- **연간**: 1회 결제, 365일 후 **수동 갱신**(자동 갱신 아님). 만료 30·7·1일 전 이메일.
- **결제 실패**: 월간 갱신 실패 → 3일 후 1회 재시도 → 또 실패하면 Free 전환 + 이메일.
- **Pro → Free 전환**: 기존 데이터는 삭제하지 않음. 평가 저장 5개 제한이 적용되어 새 평가 저장 시 "프로 복구" 안내.

### 2-B-4. 스키마 추가
```
subscriptions: id, teacher_id(FK), plan('pro_monthly'|'pro_yearly'),
  status('active'|'cancelled'|'expired'|'past_due'), portone_billing_key(NULL),
  portone_payment_id, current_period_start, current_period_end,
  cancelled_at(NULL), created_at, updated_at

payment_history: id, subscription_id(FK), amount(int, 원),
  status('paid'|'failed'|'refunded'), portone_payment_id, paid_at, created_at
```
(→ R8. 빌링키는 암호화 저장, 로그 출력 금지. 교사 계정 삭제 시 빌링키 파기 + 포트원 쪽 해지, 결제 기록은 법정 보존 기간 동안 교사 식별정보를 분리해 보관)

### 2-B-5. 학교 라이선스 (2027년 2학기 이후 본격화)
Phase 2에서는:
- `/pricing` 학교 카드 "도입 문의" → `mailto:mannote@tkad.co.kr` 또는 구글폼
- 관리자 API `PATCH /api/admin/teachers/:id/plan` → 특정 교사를 school로 수동 전환
- 세금계산서는 기존 THINKAD 사업자 인프라 활용

### 2-B-6. 교사 대시보드 제휴 배너
- 학생 화면에는 절대 광고 없음.
- 교사 대시보드 하단 `PartnerBanner`. 어드민에서 이미지·링크·노출 기간 설정.
- 교구·교재 출판사, 교원연수 기관 대상 월정액 스폰서십.
- 유저 1,000명 이상 확보 후 영업. Phase 2에서는 컴포넌트만 만들고 비활성.

## Phase 3 · 규제 대응 (11월, 운영 작업 중심)

### 3-1. 에듀집(EduZip) 등록
1. KERIS 에듀집 포털에서 공급기관 등록 신청
2. 교육부 필수기준 체크리스트 작성:

   - 수집·이용 목적 → 단원평가 생성·배포·채점·분석
   - 수집 항목 → 교사(이메일, 이름), 학생(이름 또는 출석번호, 응답 데이터)
   - 보유 기간 → 학기 단위 익명화
   - AI 외부 전송 → Claude API에 학년·단원·조건만 전송, 개인정보 미전송
3. 체크리스트를 에듀집에 게시 → 교사가 다운로드해 학운위 안건에 첨부

### 3-2. 학교 도입 안내 페이지 `/guide/school-adoption`

- 도입 절차 3단계: ① 에듀집 체크리스트 확인 → ② 학운위 안건 첨부 → ③ 심의 통과 후 사용
- 에듀집 체크리스트 다운로드, 도입 제안서 템플릿 PDF 다운로드

### 3-3. 학운위 심의 지원 키트 (PDF 4종, `public/docs/`)

4. 도입 제안서 템플릿 (학교명·학년·담당 교사명만 교체)

### 4-2. AI 프롬프트 확장
`generateQuestions`의 grade를 `3|4` → `3|4|5|6`으로 확장. 5~6학년 보강:
- **분수 연산**: 진분수·대분수·가분수 혼합 연산(통분 포함), 분수÷분수는 역수 곱셈, 대분수 곱셈은 가분수로 바꿔서 계산
- **소수 연산**: 소수×소수 소수점 위치 규칙, 소수÷소수는 나누는 수를 자연수로 만들기, 반올림·올림·버림 어림
- **비와 비율**: 분수·소수·백분율 변환, 비례식(내항의 곱 = 외항의 곱), 비례배분
- **도형·측정**: 평행사변형·삼각형·사다리꼴·마름모 넓이, π ≈ 3.14로 원의 둘레·넓이, 직육면체 겉넓이·부피, 각기둥 전개도
- **자료와 가능성**: 평균과 역추산, 띠그래프·원그래프, 가능성을 수로 표현(0~1 또는 %)

### 4-3. 자기검산 로직 확장
1. 분수 나눗셈: 역수 곱셈으로 재계산, 기약분수 여부 확인
2. 소수 나눗셈: 소수점 이동 후 자연수 나눗셈으로 재계산, 나머지가 있으면 몫·나머지 모두 검증
3. 비와 비율: 비율 = 비교하는 양 ÷ 기준량으로 재계산, 백분율 ×100 확인, 비례식 내항·외항 곱 일치
4. 넓이·부피: 공식 대입 재계산, π = 3.14 사용 확인(3.14159… 금지), 단위(cm²/cm³) 일관성
5. 평균: 합계 ÷ 개수로 역계산, 역추산 문항은 평균 × 개수 = 합계 검증

### 4-4. 데모 페이지 확장
- 학년 선택 3·4 → 3·4·5·6
- 5~6학년 샘플 문항: 단원당 난이도별 3문항 (기존과 동일 구조, `scripts/generate-demo-samples.ts`)

## Phase 5-A · 바이럴 구조 (2027년 1월)

### 5-A-1. 동학년 평가 공유
- 평가 저장 후 "동학년 선생님에게 공유" → 공유 링크 → 받는 교사가 로그인 후 "내 평가"로 복사(fork)
- 원본 수정은 복사본에 반영 안 됨 (독립 사본: 문항도 받는 교사 소유로 복제)
- Free: 받기만 / Pro: 보내기+받기
```
shared_assessments: id, original_assessment_id(FK), share_code(varchar(12) UNIQUE),
  shared_by(FK), forked_count(int DEFAULT 0), created_at, expires_at(30일)
```
- `forked_count` → 바이럴 계수 KPI 원천 데이터

### 5-A-2. 워터마크
- 학생 응시 화면 하단: 작게 "단평GO로 만든 평가" + 도메인 (반투명, 응시 방해 없음)
- PDF 리포트 하단: "이 리포트는 단평GO에서 생성되었습니다 · [도메인]" (도메인은 `SITE_URL`)

### 5-A-3. 학부모 공유 리포트 (→ R12)

- 유효 기간 7일, 로그인 불필요
- 하단에 단평GO 로고 + "선생님이 단평GO로 만든 평가입니다"

## Phase 5-B · 오답 기반 보충 문항 — 킬러 기능 (2027년 1월)

### 5-B-1. 흐름
```
[학생 평가 완료]
  → [교사 리포트 "취약 문항 보충 평가 만들기"]
  → [AI: 오답률 높은 문항의 단원·유형·난이도 입력
        → 동일 난이도 50% + 한 단계 쉬운 난이도 50% 보충 세트]
  → [교사 검수·수정 → 저장] → [학생에게 배포]
  → [원 평가 vs 재평가 비교 리포트]
```

### 5-B-2. AI 프롬프트 (→ R13)
- 입력: 원 평가 오답률 상위 3~5개 문항 정보 (단원, 성취기준, 난이도, 유형)
- 출력: 같은 성취기준의 새 문항 (같은 문항 반복 금지)
- 난이도: 오답 문항과 같은 난이도 50% + 한 단계 낮은 난이도 50%
- 문항 수: 오답 문항당 2문항 (오답 5개 → 10문항)

### 5-B-3. 비교 리포트
- 원 평가 vs 보충 평가 성적 나란히 비교, 취약 영역 개선 바 차트
- "○○ 학생: 분수의 나눗셈 정답률 40% → 80% 개선"
